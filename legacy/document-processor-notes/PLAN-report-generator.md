# Report Generator Feature Plan

**Status:** In Progress
**Created:** 2026-05-26
**Updated:** 2026-05-27
**Decision:** Approved - PDF with images via chat command

---

## Overview

Add a dedicated report generation capability to the chatbot that allows users to request structured reports via natural language. Reports are generated from indexed document data with computed statistics (not LLM-hallucinated).

**Example User Request:**
```
"Help me generate a report for 2026 rent in Central"
```

---

## Design Principles

1. **Separate Node** - Report generator is a standalone node, not mixed with existing chatbot logic
2. **Constrained Options** - Limited report types based on available data (prevents hallucination)
3. **Real Statistics** - All numbers computed from actual data, not generated by LLM
4. **Guided Flow** - System asks for missing parameters with numbered choices
5. **Bilingual** - All reports support Chinese and English

### 1. Rent Analysis (租金分析報告)

**Sections:**
1. Summary cards (count, avg rent, min, max)
2. By Property Type table
3. By Building table
4. Detailed Listings table (top 10)

**Statistics Computed:**
- `count`: Total properties
- `avg_rent_sqft`: Average rent per sqft
- `min_rent_sqft`: Minimum rent per sqft
- `max_rent_sqft`: Maximum rent per sqft
- `by_type`: {type: {count, avg_rent, avg_size}}
- `by_building`: {building: {count, avg_rent, min, max}}

### 2. Availability Report (空置單位報告)

**Sections:**
1. Summary (count, total sqft, size range, rent range)
2. By Size Category table
3. Available Units list

**Statistics Computed:**
- `count`: Available units
- `total_sqft`: Sum of all sizes
- `size_range`: {min, max}
- `rent_range`: {min, max}
- `by_size_bucket`: {bucket: {count, avg_rent}}

### 3. Market Overview (市場概覽報告)

**Sections:**
1. Market Snapshot cards
2. Property Distribution (pie chart data)
3. Recent News list
4. Web Insights (from Tavily)

**Data Sources:**
- Listings (inventory stats)
- News articles (recent market news)
- Web search (real-time trends)

### 4. Development Pipeline (發展項目報告)

**Sections:**
1. Summary (project count, total GFA, timeline)
2. Projects table
3. By Usage breakdown
4. By Developer table

**Statistics Computed:**
- `project_count`: Number of pitching decks
- `total_gfa`: Sum of all GFA
- `by_usage`: {retail, office, residential sqft}
- `by_developer`: {developer: {count, total_gfa}}

### 5. Contact Directory (聯絡人名錄)

**Sections:**
1. Summary (contact count, companies)
2. Contacts table (name, company, phone, email)

**Statistics Computed:**
- `count`: Total contacts
- `by_company`: {company: [contacts]}

### Statistics Module

All statistics computed in Python, not by LLM:

```python
def compute_rent_statistics(documents: list[dict]) -> dict:
    rents = []
    for doc in documents:
        extracted = doc.get("extracted_data", {})
        if doc["document_type"] == "listing":
            if extracted.get("rent_monthly") and extracted.get("size_sqft"):
                rents.append({
                    "rent": extracted["rent_monthly"],
                    "size": extracted["size_sqft"],
                    "rent_sqft": extracted["rent_monthly"] / extracted["size_sqft"],
                    "building": extracted.get("building_name"),
                    "type": extracted.get("property_type"),
                })
        elif doc["document_type"] == "listing_list":
            for unit in extracted.get("units", []):
                if unit.get("rent") and unit.get("size"):
                    rents.append({...})

    return {
        "count": len(rents),
        "avg_rent_sqft": statistics.mean([r["rent_sqft"] for r in rents]),
        "min_rent_sqft": min([r["rent_sqft"] for r in rents]),
        "max_rent_sqft": max([r["rent_sqft"] for r in rents]),
        ...
    }
```

### LLM Usage

LLM is only used for:
1. Generating narrative summary (optional)
2. Translating user query to parameters (if ambiguous)

LLM is NOT used for:
- Computing statistics
- Generating numbers
- Creating data tables

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Not enough data for meaningful report | Show warning if < 3 properties found |
| Inconsistent extracted data | Handle nulls, show "N/A" where data missing |
| User requests unsupported report | Show available options, guide to valid choice |
| Performance with large aggregation | Limit to 100 docs, paginate if needed |
| Hallucinated statistics | All stats computed in Python, never by LLM |

### Image Handling

```python
# In aggregator.py
def aggregate_with_images(district: str, doc_type: str = None) -> tuple[list[dict], list[dict]]:
    """Fetch documents and their images for report."""
    docs = aggregate_documents(district=district, document_type=doc_type)

    images = []
    for doc in docs:
        if doc.get("image_urls"):
            for url in doc["image_urls"][:3]:  # Max 3 images per doc
                images.append({
                    "url": url,
                    "building": doc.get("extracted_data", {}).get("building_name", ""),
                    "doc_id": doc["id"]
                })

    return docs, images[:9]  # Max 9 images in report
```
